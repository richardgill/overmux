## Server definitions

Import definition helpers from `overmux`:

```ts
import {
  defineOperation,
  defineOvermuxServer,
  defineResourceContract,
  defineStreamContract,
  defineStreamHandler,
} from "overmux";
```

`defineOvermuxServer()` defines the capabilities available from one server. It preserves types for `overmux/client` hooks and defaults omitted operation output schemas to `z.void()`.

```ts
export const serverConfig = defineOvermuxServer({
  resources: {
    // Resource definitions, keyed by resource ID.
  },
  operations: {
    // defineOperation(...) values, keyed by operation ID.
  },
  streams: {
    // defineStreamHandler(...) values, keyed by stream ID.
  },
});
```

| Option | Required | Value |
| --- | --- | --- |
| `resources` | Yes | An object of query, subscription, or derived resource definitions. |
| `operations` | No | Inline operation definitions or reusable `defineOperation(...)` values. |
| `streams` | No | An object of `defineStreamHandler(...)` definitions. |

Object keys are the IDs used by clients. See [Resources](./100-resources.md), [Operations](./200-operations.md), and [Streams](./300-streams.md) for usage guides.

## Resource handlers

A resource definition has a `contract` created with `defineResourceContract({ input, output })`. Overmux parses handler input with `input` and validates every result with `output`.

| Kind | Required handler API |
| --- | --- |
| `query` | `read(input, context) => output \| Promise<output>` |
| `subscription` | `read(input, context)` and `subscribe(input, invalidate, context) => disposer` |
| `derived` | `dependencies` and `combine(dependencies) => output` |

```ts
const count = defineResourceContract({
  input: noInputSchema,
  output: z.number(),
});

const resources = {
  count: {
    kind: "subscription",
    contract: count,
    read: () => readCount(),
    subscribe: (_input, invalidate) => {
      const stop = watchCount(invalidate);
      return () => stop();
    },
  },
};
```

`subscribe` must synchronously return a cleanup function. Overmux calls it when that client subscription, or the server runtime, closes. A derived resource reads the resources named by `dependencies`; invalidating a dependency also invalidates its dependants. See [Resources](./100-resources.md) for contracts, derived dependencies, and invalidation.

## Stream handlers

A stream contract defines `input`, `clientMessage`, and `serverMessage` schemas. Define its handler with:

```ts
const terminal = defineStreamHandler(contract, (input, context) => ({
  onMessage: async (message) => {
    // Handle a validated client message.
  },
  dispose: async () => {
    // Release per-session resources.
  },
}));
```

`open(input, context)` may return the session object or a promise for it. Its context extends the [handler context](#handler-context) with:

| API | Purpose |
| --- | --- |
| `emit(message)` | Validate and send a server message to this session. Calls after closure are ignored. |
| `fail(cause)` | Fail and close this session. A later call has no effect. |

The returned `StreamSession` may contain:

| API | Purpose |
| --- | --- |
| `onMessage(message)` | Receive validated client messages. Calls are processed in order. |
| `dispose()` | Release session resources. It may be async and is called once when the session closes. |

The stream `signal` aborts when its session or the runtime closes. Stop background work in response to it, and put resource cleanup in `dispose`. See [Streams](./300-streams.md) for stream usage from the client.

## Handler context

Inline resource, operation, and stream handlers infer valid resource IDs and inputs.

Resource and stream handlers receive a context with:

| API | Purpose |
| --- | --- |
| `invalidate(resourceId, input?)` | Ask clients to [read a resource again](./100-resources.md#invalidating-resources). Pass the resource's key in `resources`. Omit `input` to invalidate all inputs; otherwise it is validated and only matching inputs are invalidated. Unknown IDs throw. |
| `signal` | An `AbortSignal` that aborts when the request or session, or the server runtime, closes. |
| `instance.getInstanceId()` | Get this server instance's ID. |
| `instance.getDeepLinkPrefix()` | Get this instance's Overmux deep-link prefix. |

Operation handlers receive the same context plus `notifications.send(notification)`, which returns `Promise<void>`. See [Notifications](./400-notifications.md).
