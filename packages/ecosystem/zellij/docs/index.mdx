<Callout type="warning">
  Experimental: compatibility is not guaranteed.
</Callout>

`@overmux/zellij` provides typed session state, targeted operations, and browser terminal streaming for Zellij 0.45.1.

Install the package in your Overmux project, then approve the bundled plugin:

```sh
pnpm add @overmux/zellij
pnpm exec overmux integration install zellij
```

## Targeted tab operations

Register `zellijOperationHandlers({ backend })` from `@overmux/zellij/server` as your application's operations. Their inputs include:

```ts
// Move a stable tab ID, regardless of the attached clients' selections.
moveTab({ sessionName: "work", tabId: 8, direction: "left" });

// Create without changing focus, using a terminal pane's reported working directory.
createTab({
  sessionName: "work",
  fromPane: { id: 3, isPlugin: false },
  name: "tests",
  command: ["pnpm", "test"],
});

// Explicit working directories remain supported, but cannot be combined with fromPane.
createTab({ sessionName: "work", cwd: "/projects/app", name: "shell" });
```

`fromPane` accepts terminal panes only and resolves within `sessionName`. Its working directory comes from a one-off `list-panes --all --json` metadata query, not the plugin's topology snapshots. A missing source pane or session returns `not-found`. An unavailable `pane_cwd` returns an error, never a fallback directory. Creation returns `{ outcome: "success", created: { kind: "tab", tabId } }` after a plugin snapshot confirms the tab exists.

Moves preserve Zellij 0.45.1 semantics: swap adjacent tabs, rotate the first tab to the end when moving left, and rotate the last tab to the start when moving right. A single-tab move succeeds without waiting for an event. A missing target returns `not-found`; other moves confirm the resulting order against a newer plugin snapshot. Concurrent topology changes can produce a bounded reconciliation error instead of success.

## Compose a terminal

```tsx
import { useZellijTerminal, ZellijXterm } from "@overmux/zellij/react";

const terminal = useZellijTerminal({ stream });

<ZellijXterm terminal={terminal} />;
```

Call the hook inside your view component. The hook owns connection cleanup; the application renders `terminal.error` and its own close button. Unmounting only `ZellijXterm` keeps the connection alive. Unmounting the hook owner closes that attached client, not the Zellij session. Local scrollback defaults to zero, with an explicit override through `options={{ scrollback: 1_000 }}`.

Style the terminal through `className` and `style`; there is no additional Zellij wrapper or stylesheet import.

### Renderer remount limitation

**The connection survives renderer unmount, but the terminal state does not.** Unmounting `ZellijXterm` destroys xterm's screen, cursor/input modes, and partially parsed escape sequences. Only pending and future bytes reach a new renderer; already acknowledged output is not replayed. An update to one line may appear without earlier screen contents, or the screen may stay blank if no output is pending. A partial escape sequence can also be interpreted incorrectly after losing its prefix.

Keep the component mounted when hiding a view, retaining its usable dimensions:

```tsx
<ZellijXterm
  terminal={terminal}
  active={visible}
  style={{ visibility: visible ? "visible" : "hidden" }}
/>
```

This keeps output processing and terminal state alive; `active={false}` gates input, not output or sizing. Avoid relying on a resize to repair a destroyed renderer: unchanged dimensions are ignored, and changed dimensions may resize shared panes without guaranteeing a repaint.

In development, StrictMode can discard an xterm that already received buffered output and create an empty replacement. Not every fresh mount is affected; keeping the transport alive during effect replay is not screen-state preservation.

Replacing the fixed stream creates a new PTY client and obtains fresh attachment output, but does not guarantee the previous client's tab/pane selection. Automatic renderer-state restoration is not implemented.

See the [usage and API documentation](./index.md) for server setup, custom renderer attachment, and lifecycle details.
